# Security policy

This policy covers every repository owned by [@resnickio](https://github.com/resnickio) that doesn't have a `SECURITY.md` of its own.

## Reporting a vulnerability

**Please don't open a public issue with details.**

- **Use GitHub's private vulnerability reporting** where it's offered: open the repository's **Security** tab and choose **Report a vulnerability**. Only the maintainer can see the report.
- **If that button isn't there,** open an issue saying only that you have a security report to share privately. Leave out every detail. You'll be contacted to arrange a private channel.

A useful report says:
- what is affected: the repository, plus the version, tag or commit
- how to reproduce it
- what an attacker could do with it

## What to expect

These are personal projects with a single maintainer.
- Reports are acknowledged as quickly as possible.
- Fixes are prioritized by impact.
- There is no bug bounty.

## Supported versions

Only the latest release receives fixes. For repositories without releases, that means `main`.
